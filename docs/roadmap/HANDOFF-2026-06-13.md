## 2. AVM accuracy re-plan — "how low can APE go" (delivered, not yet built)

Honest framing: don't benchmark vs Zillow's ~2% (that's on-market, peeks at list price).
**Off-market realistic target ~6–7% blended in dense FL metros; irreducible floor ~3–5%.**
Our 18.7M-sale comp density is the structural edge. Path to sub-9% = **features + modeling,
NOT segmentation** (tested). Three waves:

- **Wave 0 (days, data we already have):** segment-scope out land/junk; **two-stage $/sqft**
  (fixes the price-tier spread); wire in already-scraped signals to `ParcelFeature` (code
  violations 10.8k, homestead flag, land-vs-improvement value split, vacancy code,
  sale-history); add **FEMA flood zone** (free ArcGIS on existing lat/lng) + waterfront
  distance; repeat-sales submarket time index. → ~9–10% blended; residential headline sub-9%.
- **Wave 1 (weeks, the real unlock):** **CAMA detail-page ingest** (qPublic + iasWorld + BS&A
  + metro customs) for beds/baths/**quality-grade/condition/pool** — the condo fix and the
  off-market floor. Building permits (Accela + open-data) = renovation-recency. School zones.
  → true hedonic; ~7–8%.
- **Wave 2 (frontier):** MLS-surface listing data (list price/DOM/remarks — Zillow's 1.74%
  on-market vs 7.20% off-market = ~4× lever for listed inventory); CV exterior-condition from
  Street View/appraiser photos (Cape Analytics +7.7%); **calibrated per-property confidence
  intervals** (quantile/conformal — arguably the highest-value item for a buy-box: auto-approve
  tight deals, route wide ones to manual). → toward ~6%.

Recommended next AVM probe (cheap, data we have): **two-stage $/sqft model**. NOT started —
needs founder go-ahead. Note: beds/baths over-claimed by one researcher; SOTA says they're
largely collinear with sqft (modest marginal value). The real levers are condition, location
granularity, comps.

## 3. OPS-8 captcha gate — strategy (decided this session)

What's actually blocking (verified in code):
- **Landmark** (PB/Lee/Levy/Hernando/Citrus official records) = **reCAPTCHA v2**
- **Probate-MVC** (Orange/Pinellas/Broward) = **reCAPTCHA v2** ← the M3.1 blocker
- **Miami-Dade** ORI = **reCAPTCHA v3** (score-based, "self-mint")

Options (in order of preference):
1. **Records request (cleanest, proven).** OPS-7/SDF was unblocked by emailing FL DOR a
   records request — they delivered bulk files. Same play works for probate/official records
   via the Clerk of Court. Captcha-free, green-zone, legally clean.
2. **Find captcha-free PUBLIC bulk endpoints** (open-data/ArcGIS/Socrata/FTP/doc-library).
   Discovery sweep launched this session — see §4 (it failed on session limit; re-run).
3. **Miami-Dade v3 may self-mint for free** — stealth Playwright + residential proxy often
   passes v3 with no solver. Worth testing before paying.
4. **2captcha** (the wired solver, `lib/scrapers/base/captcha-solver.ts`) — ~$1–3/1k solves;
   a one-time probate backfill is single-digit dollars + a ~$10 account. **For a one-time job
   this is cheaper than building/maintaining an OSS solver.** The actual OPS-8 ask is just
   "sign up + fund $10 + set `TWOCAPTCHA_API_KEY`."
5. **OSS reCAPTCHA-v2 solver** (Whisper audio-challenge bypass) — drops into the existing
   provider-agnostic `solveRecaptcha(sitekey, pageUrl)` hook. Viable but **flakier** (Google
   detects audio automation; needs residential proxy + low volume) and a maintenance cost.
   There is NO OSS solver for v3 (no challenge to solve).

**BOUNDARY (decided):** we do **NOT** enumerate other requesters' per-request fulfillment
folders (e.g. walking the DOR `~Public Records/~<requestID>/` IDs). That's an IDOR into data
delivered to other parties — the *US v. Auernheimer* ("weev") fact pattern, materially
different from the *hiQ v. LinkedIn* public-at-large scraping that's protected. Real legal +
relationship risk (would torch the DOR records-request channel, a genuine asset). Our OWN
fulfillments are 100% fine. We get the same data legitimately via (1) and (2) + the email
automation that makes requesting scale.
